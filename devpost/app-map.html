ClauseMap / source guide

Where the evidence comes from.

ClauseMap checks one public GitHub repository at a pinned default-branch commit. It reports what the available evidence supports, then keeps human declarations separate. This map is a reference route through the finished proof of concept.

One real action

Enter a repo URLsrc/App.tsx → parseRepositoryUrl
Fetch a snapshotInspectionController.run → inspectGitHub
Decide each statusbuildMachineReport checks commit, tree, and files
Inspect the evidenceInspectionMap → EvidenceInspector

GitHub REST API supplies the machine observations. The browser stores only manual confirmation flags, keyed by normalized repository identity; it does not restore an old machine report after refresh.

Three-stop reference route

  1. Start and re-check: find start and submit in src/App.tsx. Both route a parsed repository into a fresh controller run; the page shows a checking state until that run returns.
  2. Pin and classify: find inspectGitHub in src/githubClient.ts, then buildMachineReport in src/inspectionEngine.ts. The client fetches metadata, default-branch commit, and matching recursive tree. The report permits Missing only when a complete trusted tree lacks the regular file.
  3. Show the limit: find EvidenceInspector in src/App.tsx and rules in src/rules.ts. The inspector shows observation, pinned source, official-rule context, limitation, and next action. Manual nodes use src/manualConfirmationStore.ts and never become machine Verified.

To change this, start here

Official wording or source link: src/rules.ts; recheck the primary rule before editing.

GitHub error handling: classifyHttp in src/githubClient.ts, then the matching fixture in tests/githubClient.test.ts.

Filename or Missing semantics: buildMachineReport in src/inspectionEngine.ts and tests/inspection.test.ts. Preserve the complete-tree threshold.

Noir Pink presentation: src/App.tsx and src/styles.css. Keep status words visible; color alone is not the result.

Manual confirmation persistence: src/manualConfirmationStore.ts and tests/manualConfirmationStore.test.ts.

A practice to reuse

The approved devpost/spec.md made “Missing only after a complete, commit-pinned file tree” a testable rule. tests/inspection.test.ts covers truncated and complete trees, and the live octocat/Hello-World check showed a one-entry complete tree with three Missing findings. On another evidence-based product, define the exact observation that permits each strong claim before building the UI around it.
